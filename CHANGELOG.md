# Changelog

## 0.2.2 (2026-10-15)

AttrSchema::validate and the validation attr parsers used to return on the first problem they hit, so a bad attribute only ever showed you one error. Now they collect: every check pushes into a SynBuffer from liaise_proc_macro, and it hard fails once at the end with everything it found. A typo the did-you-mean already caught isn't reported a second time as a missing key or a broken requires. Also added CI that tests on stable and 1.85 and publishes to crates.io from main.

### AttrSchema::validate collects

- one SynBuffer (`errs`) for the whole call. every check pushes into it and keeps going, and the end is `errs.finish_with(result)` instead of `Ok(result)`, so it hard fails only after all the checks ran and the error carries every problem: [src/schema.rs L214-L219](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/src/schema.rs#L214-L219), [src/schema.rs L329](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/src/schema.rs#L329). old end: [src/schema.rs L317](https://github.com/jameshuntt/simple_impl_attr_kit/blob/824f66b009e3c745bd08281936d0f2f31ea14074/src/schema.rs#L317).

### the did-you-mean

- with everything collected, one typo would come back twice. `nmae` gives unknown `nmae`, and then missing required `name` too, because `name` isn't in `working`. same with a requires rule: `count = 1, flg` would also give "`count` requires `flag`". now there's a `suggested` set with every key the did-you-mean pointed at: [src/schema.rs L235-L237](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/src/schema.rs#L235-L237), [src/schema.rs L243-L246](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/src/schema.rs#L243-L246). the required check skips a key that's in it: [src/schema.rs L295-L297](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/src/schema.rs#L295-L297), and so does the requires loop: [src/schema.rs L311-L313](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/src/schema.rs#L311-L313).
- proof: `nmae` gives only the unknown key error: [tests/collect.rs L40-L46](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/tests/collect.rs#L40-L46). `count = 1, flg` gives only the unknown key error, no requires error: [tests/collect.rs L48-L54](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/tests/collect.rs#L48-L54).

### validation attrs

- `parse_validation_attrs` used `?` on every attribute, so the first bad `#[validate]`, `#[one_of]` or `#[at_least_one_of]` stopped the loop and dropped the rules already read: [src/validation.rs L110-L124](https://github.com/jameshuntt/simple_impl_attr_kit/blob/824f66b009e3c745bd08281936d0f2f31ea14074/src/validation.rs#L110-L124). the loop is in `parse_validation_attrs_into` now. each attribute's result goes through `errs.absorb`, and a rule is pushed only if it read clean: [src/validation.rs L119-L137](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/src/validation.rs#L119-L137). `parse_validation_attrs` keeps its signature and is a wrapper with its own SynBuffer: [src/validation.rs L110-L114](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/src/validation.rs#L110-L114).
- `parse_field_validation_attrs` started with `parse_validation_attrs(attrs)?`, so a bad `#[one_of]` meant the `requires`, `invalid_without`, `only_pair_with` and `conflicts_with` on that field were never read, and each of those used `?` too: [src/validation.rs L144-L167](https://github.com/jameshuntt/simple_impl_attr_kit/blob/824f66b009e3c745bd08281936d0f2f31ea14074/src/validation.rs#L144-L167). now `parse_field_validation_attrs_into` hands the same `errs` down to `parse_validation_attrs_into` and absorbs each field rule the same way: [src/validation.rs L163-L189](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/src/validation.rs#L163-L189). the old name is the same kind of wrapper, same signature: [src/validation.rs L151-L158](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/src/validation.rs#L151-L158).
- the two `_into` functions are public, for a caller that collects: the attr errors go into the caller's SynBuffer and the rules that did read come back, so they can still be checked: [src/validation.rs L116-L118](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/src/validation.rs#L116-L118). exported from lib.rs: [src/lib.rs L80](https://github.com/jameshuntt/simple_impl_attr_kit/blob/824f66b009e3c745bd08281936d0f2f31ea14074/src/lib.rs#L80) to [src/lib.rs L80-L83](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/src/lib.rs#L80-L83).
- proof: `#[one_of(1)]` and `#[requires(5)]` are bad, `#[at_least_one_of("a", "b")]` and `#[conflicts_with("c")]` are fine. the buffer ends up with 2 errors and the spec still has both good rules: [tests/collect.rs L56-L72](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/tests/collect.rs#L56-L72).

### CI

- there was no CI before. .github/workflows/ci.yml runs on every push and pull request, with `permissions: contents: read`: [.github/workflows/ci.yml L7-L12](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/.github/workflows/ci.yml#L7-L12).
- test job: stable and 1.85, `fail-fast: false` so one toolchain failing doesn't cancel the other, and both toolchains run the same `cargo test --all-features`: [.github/workflows/ci.yml L20-L26](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/.github/workflows/ci.yml#L20-L26), [.github/workflows/ci.yml L41-L46](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/.github/workflows/ci.yml#L41-L46).
- liaise_proc_macro is a path dependency, so CI clones it to `../liaise_proc_macro` first. it tries the same branch name (so a change across both crates gets tested together), falls back to the default branch, and prints the branch and short sha it built against: [.github/workflows/ci.yml L14-L17](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/.github/workflows/ci.yml#L14-L17), [.github/workflows/ci.yml L29-L37](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/.github/workflows/ci.yml#L29-L37). the publish job does the same clone: [.github/workflows/ci.yml L58-L66](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/.github/workflows/ci.yml#L58-L66).
- publish job: only on a push to main, only after the test job passes, one run at a time (`concurrency: publish`), with `id-token: write` for crates.io trusted publishing: [.github/workflows/ci.yml L48-L55](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/.github/workflows/ci.yml#L48-L55).
- it asks crates.io for this name and version first (read from `cargo metadata`). 200 means it's already there and publish is skipped, 404 means publish, anything else fails the job: [.github/workflows/ci.yml L68-L77](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/.github/workflows/ci.yml#L68-L77).
- the publish token comes from `rust-lang/crates-io-auth-action` during the run, no stored token: [.github/workflows/ci.yml L4](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/.github/workflows/ci.yml#L4), [.github/workflows/ci.yml L78-L84](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/.github/workflows/ci.yml#L78-L84).
- any uncommitted change besides Cargo.lock stops the publish. Cargo.lock is the one file allowed to differ, because the cloned sibling can be at another version: [.github/workflows/ci.yml L86-L91](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/.github/workflows/ci.yml#L86-L91).
- `cargo publish --allow-dirty` retries up to 30 times, 30s apart, but only when the error says a dependency isn't on crates.io yet, so crates released together go out in dependency order. any other error fails right away: [.github/workflows/ci.yml L92-L102](https://github.com/jameshuntt/simple_impl_attr_kit/blob/7e6f266c0adefecc27849057921f985f2effb04e/.github/workflows/ci.yml#L92-L102).
